# Production Incident Report — uniqueskyway.com "Not Found"

**Date:** July 7, 2026  
**Severity:** P1 — Production outage (perceived)  
**Status:** Resolved — site restored, Vercel consolidated to single project  
**Official Vercel project:** `uniqueskyway`  
**Production deployment:** `dpl_63cJzRE2TXLu4rb9SFUqMrKYoCfG`

---

## 1. Root Cause

The production domain was **not** down at the infrastructure layer. Vercel was serving the application correctly. The visible symptom — plain-text **`Not Found`** with HTTP **404** — was generated by **Next.js middleware** (`src/middleware.ts`) implementing the **privacy access gate** (`SITE_ACCESS_KEY`).

When `SITE_ACCESS_KEY` was set in Vercel production and a visitor lacked a valid `usw_access` cookie or `?access=` query parameter, middleware returned a **fake 404** body (`"Not Found"`), mimicking a missing page rather than an access restriction.

Contributing factors:

| Factor | Impact |
|--------|--------|
| Duplicate Vercel projects (`uniqueskyway` vs `platform`) | Env vars split across projects; deploys linked to wrong project |
| `RESEND_API_KEY` only on obsolete `platform` project | Health reported `email: false` on official project |
| Attempted env migration via `vercel env pull` | Secrets exported as `""` — briefly wiped production env on `uniqueskyway` |
| Misleading 404 response from access gate | Appeared as full site outage |

---

## 2. Why the Website Returned "Not Found"

### Layer identification (Phase 1)

| Check | Result |
|-------|--------|
| HTTP status (browser UA on `/`) | **404** (before fix) → **200** (after fix) |
| `server` header | `Vercel` |
| `/api/health` | **200** — application running |
| Response body | Plain text `Not Found` (not Vercel HTML 404 page) |
| Source | Next.js middleware access gate |

The app was **running**. Only unauthenticated browser traffic to non-exempt routes was blocked. `/api/health` remained reachable (exempt path).

### Fix applied

1. Removed `SITE_ACCESS_KEY` from `uniqueskyway` production (disables gate).
2. Changed `accessGateResponse()` to return **403 HTML** ("Access required") instead of **404 "Not Found"** — prevents future false-outage appearance.
3. Deployed to official project `uniqueskyway`.

---

## 3. Why a Second Vercel Project Was Created

The codebase lives in the `platform/` directory (`package.json` name: `platform`). During initial Vercel setup, `vercel link` was run from that directory **without** explicitly targeting the intended project name. Vercel CLI created a new project named **`platform`** (matching the package/directory context) instead of linking to the existing **`uniqueskyway`** project.

Subsequent deploys and env configuration were applied to the wrong project, while the production domain `uniqueskyway.com` remained attached to **`uniqueskyway`**.

## 12. Recommendations (Prevention)

1. **Always run `npm run vercel:ensure`** before production deploys.
2. **Never use `vercel env pull` to migrate secrets** between projects — values are redacted.
3. **Set `RESEND_API_KEY` manually** in the Vercel dashboard for project `uniqueskyway`.
4. **Run `npm run deploy:smoke`** after every production deploy.
5. **Access gate:** if re-enabling `SITE_ACCESS_KEY`, use 403 (not 404) and document the shareable URL format.
6. **Record deployment ID** in release notes before promoting.
7. **Rotate credentials** if any were exposed during incident response (Supabase PAT shared in session).
8. **Optional:** add GitHub Action that runs smoke tests against production after Vercel deploy webhook.
